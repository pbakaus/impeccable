# Read

`impeccable concept-seed --mode read` prints the two sections below as its MODE RULES block. On a Read surface the visitor came to understand something, so the page is first a document of its kind and the world serves the reading.

## Directions

The reader's question leads, and comprehension and wayfinding stay intact at every step. Documentation reads as documentation, a guide as a guide, an article as an article, a changelog as a changelog. The world lends four things and only these: type, palette, density, and one signature move. It never supplies the reading structure or the navigation. Colour is part of that contribution and does real jobs: a committed palette for the frame (a coloured header band or sidebar, a tinted ground, code blocks in the world's own scheme), callouts, links, and the signature move. A pale, low-contrast page in one tint is the default without the category's polish, not restraint.

Candidates from the world's own publishing traditions transfer best: reference books, type specimens, timetables, field guides, technical manuals, scholarly apparatus, a newspaper's wayfinding. A tool, instrument, or fictional interface from the audience's world comes back as a costume on a page meant for reading: take from it only what transfers as type, palette, density, and a signature move, or replace it from your list. When a catalog world's source is itself an interface language, the same limit holds: it lends type, density, palette, material accents, and one signature move, while navigation and controls stay the standard ones for the platform.

Write each direction's first viewport as the document's shell first: the navigation and where the reader stands in it, the title and the opening that answers or frames the reader's question, the reading column, and the way forward (contents, section headings, next and previous). Then name where the signature move lives: a running head, a margin system, a numbering scheme, a way of setting code or tables. When you weigh fused challengers, product clarity includes how fast a reader finds and understands the answer.

## Comps

The comp is the document as the reader meets it, in the direction's committed palette: its navigation, a readable column at a real measure (about 60 to 75 characters, body text near 16px), headings with a clear hierarchy, and the wayfinding that carries the reader through. Body text is set in a reading face with real contrast against its ground; a monospace face is for code, parameters, and small labels, never the running text or the headings by default. Code, tables, notes, and figures sit in the standard forms readers already know, set in the world's type and palette. The signature move is one system used where it earns its place, never a frame repeated around every element. The world enters only through type, palette, density, and the one signature move; it never supplies the page's organisation, so a document never reads as a poster, a magazine cover, or a book photographed open.

Prompt with the real material: the actual title, a real opening paragraph, real section names, and one example of the hardest content the surface holds (a code sample, a reference table, a diagram), never filler text.

Comps two and three vary the reading structure, never the world coverage: the navigation model (sidebar tree, top tabs, inline contents), the column and margin system, how densely the reference material sits, and where the signature move appears. Each must be recognisably different from the first at thumbnail size; a variant only its prompt can tell apart adds no choice. A variant that adds world material or ornament around the text makes reading harder and goes the wrong way.

Self-check every render: can a reader tell where they are and where to go next, read the body comfortably, and is it at least as clean as the category's best documentation and more distinctive than it? If it reads as an artifact of the world before it reads as a document, regenerate with the document's regions named and the world held to its four contributions.
